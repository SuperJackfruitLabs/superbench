# Proposed SuperBench reader candidate

This is a disabled, fixture-backed product reader, beside the earlier design in
`docs/mockups`. `index.html` consumes only the pinned proposed observation data
under `contract/`. It has no transport factory, listener, account credential,
operator token, daemon connection or live file/process access. Content Security
Policy denies all connections. There is no launch script or network proxy.

Inventory shows logical host, used/quota/allocated observations, current holder,
last confirmed checkpoint and complete grouped members. Available zero is distinct
from unavailable. Latest-only evidence is not a fabricated timeline; unknown
confirmation time remains unknown. Unleased, held and blocked display values do
not enable a write action. All display/task strings become text nodes, never
HTML or navigable child-supplied links.

`reader-model.test.mjs` runs the same structural/semantic/lexical corpus against
the actual portable JavaScript codec. Source pins identify the proposed Treaty
revision and original/generated bytes. The sync script performs type erasure and
browser WebCrypto/base64 substitutions only; it does not implement authorization,
Git/filesystem reads, snapshot consistency or writer fencing.

Run `node --test web/*.test.mjs` with the pinned `.node-version`. The repository
check runs these tests before the existing Go checks. Node is a CI/developer tool,
not a new CLI/daemon runtime dependency. Refresh intentionally with
`node scripts/sync-reader-contract.mjs --source /absolute/clean/treaty` after
reviewing its committed proposal and expected revision in the pin test.

Visual browser rendering remains **unverified**. This work does not bypass an
artifact-access denial using a server, proxy or browser workaround. No live viewer
adapter may be enabled until the owner decision, authentication/scoped read
crossing, producer safety and consuming integration are accepted and verified.
Files/diffs/log reads, checkpoint-history storage, terminal read/write attachment,
network authentication and other suite consumers remain Phase 2 work. This
candidate does not complete that phase or Phase 1's operational pilot.
